# `repo-reuse-policy`: under `BAKAR_REPO_POLICY=reuse` (the default for every routed meta-avocado build and always forwarded by `--on`), classify each pinned repository of the merged kas configuration as frozen (at its pin and clean, so a generated overlay sets `url: null` and kas performs no version-control operation on it), missing (kas clones it at its pin) or side (off its pin or dirty, so kas is pointed at a side checkout under `<workspace>/.bakar/pins/<repo>/<commit12>` that bakar never modifies), so a build in a shared release workspace never moves an existing clone; every repository that cannot be served is reported in one refusal with its HEAD, pin, clean or dirty state, pin-commit presence and the `bakar sync` line that repairs it; in host mode a diverged `openembedded-core` takes a side checkout paired by a `bitbake` symlink to the frozen `bitbake` clone, while a diverged `bitbake` always blocks; every reuse build holds a shared whole-run lock on `<workspace>/.bakar/repos-in-use.lock` that `bakar sync` needs exclusively

**Delivered by:** bakar-on-release-workspace-dispatch, remote-dispatch-stale-workspace
**Modules touched:** other, tests
